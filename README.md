# FINAL Bundle — باندلینگ ساده ورژن ۴

یک PWA سبک و راست‌چین برای تولید خودکار بسته‌های کارتخوان و کش‌لس توسن تکنو. برنامه با HTML، CSS و JavaScript استاندارد ساخته شده و برای اجرا به نصب Node.js، npm یا فرایند Build نیاز ندارد.

## منطق محاسبات نسخه ۴

- **قیمت قبل از باندل کارتخوان** = قیمت پایه کارتخوان + بودجه بازاریابی هر کارتخوان.
- بودجه بازاریابی فقط برای ساخت قیمت قبل از باندل استفاده می‌شود و **هرگز** وارد بودجه باندلینگ کش‌لس یا محاسبه ظرفیت مالی باندل نمی‌شود.
- **بودجه باندلینگ هر کش‌لس** = قیمت فروش کش‌لس − بهای تمام‌شده کش‌لس − مبلغ مارک‌آپ کش‌لس.
- درصد مارک‌آپ به‌صورت خودکار از مبلغ مارک‌آپ تقسیم بر بهای تمام‌شده محاسبه و زیر فیلد نمایش داده می‌شود.
- موتور تعداد ثابت POS در بسته را با تعدادهای مختلف Cashless (از ۱ تا سقف واردشده، حداکثر تا تعداد POS) ترکیب می‌کند.
- بودجه کل هر ترکیب = بودجه باندلینگ هر کش‌لس × تعداد کش‌لس.
- حداکثر تخفیف قابل‌تخصیص به هر POS از تقسیم بودجه کل بر تعداد POS به‌دست می‌آید.
- قیمت تعدیل‌شده POS = بیشینه قیمت رقابتی بازار و (قیمت قبل از باندل − تخفیف قابل‌تخصیص هر POS). قیمت هرگز پایین‌تر از کف رقابتی نمی‌رود.
- **بودجه مصرف‌شده** = تخفیف هر POS × تعداد POS.
- **بودجه باقی‌مانده** = بودجه کل باندلینگ − بودجه مصرف‌شده.
- **قیمت واقعی کش‌لس در باندل** = بهای تمام‌شده + مبلغ مارک‌آپ + (بودجه باقی‌مانده ÷ تعداد کش‌لس). این شاخص فقط در نمای مدیریت نمایش داده می‌شود و قیمت فروش ثبت‌شده یا سود خالص حسابداری نیست.
- **مبلغ کل بسته** = (قیمت تعدیل‌شده POS × تعداد POS) + (قیمت فروش کش‌لس × تعداد کش‌لس).

## امکانات

- ورودی‌های قابل‌تنظیم برای قیمت‌های POS و Cashless، بودجه بازاریابی، مبلغ مارک‌آپ و تعداد محصولات.
- تولید خودکار گزینه‌های بسته با افزایش تعداد کش‌لس و مشاهده تغییر قیمت کارتخوان.
- نمای مدیریت با بودجه مصرف‌شده، بودجه باقی‌مانده و قیمت واقعی کش‌لس در باندل.
- نمای شبکه فروش بدون نمایش جزئیات داخلی بودجه.
- خروجی CSV متناسب با نمای فعال؛ فایل نمای کارگزار شامل شاخص‌های داخلی مدیریت نیست.
- چاپ / ذخیره PDF از مرورگر.
- PWA قابل نصب روی HTTPS و Cache برنامه برای دسترسی آفلاین.
- محاسبات در مرورگر انجام می‌شوند؛ ورودی‌ها به سرور ارسال یا در Local Storage ذخیره نمی‌شوند.

## اجرای محلی

می‌توانی `index.html` را برای دیدن رابط باز کنی؛ اما Service Worker و نصب PWA در مرورگر به HTTPS یا `localhost` نیاز دارند. برای تست محلی با Node.js نصب‌شده:

```bash
npx http-server .
```

سپس آدرس localhost را در مرورگر باز کن.

## انتشار از طریق GitHub Pages

1. فایل ZIP را استخراج کن.
2. تمام محتویات پوشه پروژه را (از جمله پوشه `.github`) به ریشه مخزن GitHub آپلود کن.
3. در GitHub، وارد **Settings → Pages** شو.
4. در بخش **Build and deployment**، گزینه **GitHub Actions** را به‌عنوان Source انتخاب کن.
5. فایل workflow موجود، سایت استاتیک را پس از Push به شاخه `main` منتشر می‌کند.
6. پس از اتمام workflow، URL منتشرشده را از بخش Pages باز کن. HTTPS برای نصب PWA لازم است.

اگر نام شاخه اصلی مخزن `main` نیست، شاخه در فایل `.github/workflows/pages.yml` را با نام واقعی تطبیق بده.

## آزمون موتور محاسباتی

با Node.js نسخه ۱۸ یا بالاتر، از ریشه پروژه اجرا کن:

```bash
node --test tests/engine.test.js
```

## نکته مهم درباره دسترسی‌ها

تفکیک «مدیریت» و «شبکه فروش» در این نسخه، تفکیک نمایشی سمت مرورگر است و مرز امنیتی واقعی برای داده‌های محرمانه محسوب نمی‌شود. برای استفاده سازمانی واقعی با داده محرمانه، باید احراز هویت و کنترل دسترسی سمت سرور اضافه شود.
